# 生产部署

企业名单工作台由四部分组成：Vite Web UI、Supabase 数据库与 Edge Functions、Provider Worker、可选的 WorkBuddy/Agent Skills。只部署静态前端不能执行名单查询、文件导入、企查查核验或公开信息报告。

## 1. 后端

1. 创建 Supabase 项目并应用 `supabase/migrations`。
2. 部署 `bootstrap-admin`、`workbench-api`、`workbench-jobs`、`mcp` 等 Edge Functions。
3. 在服务端 Secret 中配置至少 24 字节的 `WORKBENCH_BOOTSTRAP_TOKEN`。
4. 将 `WORKBENCH_PUBLIC_ORIGIN` 固定为 Supabase Functions 所在的 HTTPS Origin，例如 `https://<project-ref>.supabase.co`。生产环境缺失或使用 HTTP 时 MCP 会拒绝启动，不会从 `Host` / `X-Forwarded-Host` 猜测外部地址。
5. 保持公开 Email/SMS 注册关闭；首位管理员创建成功后，引导页面会永久关闭。
6. 为获客助手、企查查和联网搜索配置服务器端凭证或可执行程序路径。凭证不得使用 `VITE_*` 变量。

使用仓库的 GitHub Actions 部署时，工作流会把受信任的 `SUPABASE_URL` 明确写为该 Origin；只有通过自定义代理域名暴露 MCP 时，才需要创建 Repository Variable `WORKBENCH_PUBLIC_ORIGIN` 覆盖它。初始化脚本也会根据项目引用自动写入同一地址。

## 2. Provider Worker

构建阶段：

```sh
npm ci
npm run build:worker
```

运行阶段：

```sh
SUPABASE_URL='<项目地址>' \
SUPABASE_SERVICE_ROLE_KEY='<服务端密钥>' \
NODE_OPTIONS='--max-old-space-size=512' \
npm run worker:start
```

Worker 使用服务角色，只能运行在可信服务器，不得打包进浏览器或公开下载物。生产运行环境还应设置硬资源边界：单实例至少 512 MiB、建议上限 768 MiB，CPU 上限 1 核，单次任务运行上限 5 分钟，并启用异常退出自动重启。内存、CPU 与进程时限应由容器或进程管理器强制执行，不能只依赖应用内计时器。

XLSX 在交给 ExcelJS 前会检查 ZIP 条目数、总解压体积、单条目体积、压缩比、加密标记和危险路径；压缩后文件大小限制不能替代这些检查。部署层的内存和 CPU 边界仍然必须保留，作为解析库异常与未知格式的第二道防线。

## 3. Web UI

```sh
VITE_SUPABASE_URL='<项目地址>' \
VITE_SB_PUBLISHABLE_KEY='<公开发布密钥>' \
npm run build
```

将 `dist` 部署到支持 SPA 回退的静态站点。公开发布密钥受 RLS 保护；服务角色密钥、获客助手 Key、企查查配置和联网搜索 Key 不得进入 `dist`。

## 4. 发布门禁

```sh
npm run typecheck
npm run typecheck:worker
npm run lint
npm run test:unit:all
npm run build
npm run build:worker
npm run compliance:generate
npm run compliance:check
```

发布归档应包含 `compliance/sbom.cdx.json`、`compliance/THIRD_PARTY_LICENSES.txt`、`LICENSE.md` 和 `THIRD_PARTY_NOTICES.md`。任何合规阻塞项都必须在发布前解决。

## 5. WorkBuddy 与其他 Agent

`integrations/workbuddy-skill` 包含两套独立 Skill：企业名单工作台、企业公开信息报告。它们只描述业务编排和安全边界，不携带供应商凭证。部署环境必须提供工作台 MCP/REST 地址；没有基址时 Skill 只返回路由片段，不能猜测生产域名。

## 6. 首次验收

使用 10–50 家真实企业跑通：管理员初始化、数据源测试、获客助手取数或文件导入、字段映射、规则、企查查核验、Ego Lite 报告、CSV/XLSX/JSON/HTML 导出。分别检查桌面端、移动端、Web UI、MCP 与 REST 读取结果是否一致。
