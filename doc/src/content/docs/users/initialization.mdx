# 初始化企业名单工作台

初始化完成后，用户无需 Agent 即可使用全部 GUI 流程。

## 1. 创建首位管理员

部署方必须先在 Supabase Edge Function 的服务端 Secret 中设置 `WORKBENCH_BOOTSTRAP_TOKEN`。它至少为 24 字节的高熵随机值，不得使用前端 `VITE_*` 变量、提交到 Git 或写入数据库。

首次打开 Web UI，输入部署方提供的初始化码、管理员姓名、邮箱和密码。系统通过 `bootstrap-admin` 服务端入口原子占用初始化资格，并使用 Supabase Auth Admin API 创建首位管理员；成功后自动登录并进入工作空间初始化。初始化完成后，即使继续持有同一初始化码也不能再次创建账号。

Supabase 的公开 Email、SMS 和通用 signup 必须保持关闭。后续成员只能由已有管理员在系统内创建，或通过已完成域名与成员策略验收的组织 SSO 加入。

## 2. 创建工作空间

首位管理员登录后，填写工作空间名称和 Slug。系统一次性创建租户工作空间、Owner 成员关系、企查查、获客助手、文件上传三类初始连接、供应商映射说明和可编辑空规则模板。该步骤不写入供应商 API Key，也不会把未验证连接标成可用。

## 3. 配置数据源

在“数据源”页面新增连接：

- 获客助手：配置金蝶征信授权，测试名单检索及已订阅的单企报告能力。
- 企查查：配置用户自己的授权，选择允许使用的能力，并逐项测试。
- 文件上传：无需外部凭证；先确认允许的文件类型、大小和保存期限。
- Web 证据：按需配置搜索服务，默认关闭批量自动补证。

密钥保存在服务端 Secret/Vault 中。页面只显示连接名称、能力范围、最后测试时间和健康状态，不显示明文凭证。

## 4. 设置默认来源策略

选择企业身份匹配、字段展示优先级、冲突处理和数据保留期限。统一社会信用代码优先用于跨来源匹配；仅名称相似时进入人工确认，不自动合并。

## 5. 创建首个规则模板

在规则页面选择可用字段，配置硬性条件、排序或加减分条件、风险门禁和缺失值处理方式。发布后的版本不可直接修改，只能复制为新版本。

## 6. 验证完整流程

使用一批真实但范围可控的数据完成：取数或上传、映射确认、规则运行、证据审阅和导出。只有 GUI、API 和 MCP 返回一致结果，初始化验收才算完成。
