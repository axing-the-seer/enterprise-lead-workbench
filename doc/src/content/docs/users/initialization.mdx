# 初始化企业名单工作台

本地版和多用户部署共用同一套数据库权限与任务系统，但用户的首次体验不同。个人本机安装不需要邮箱账号或管理员初始化码。

## 本地单用户模式（默认）

1. 安装 Node.js 22、Docker 和 Make。
2. 在项目目录执行：

   ```sh
   npm ci
   npm run start:local
   ```

3. 打开 `http://127.0.0.1:3101/`。
4. 首次只输入两次相同的访问密码（至少 12 位）。系统自动创建本机内部身份、工作空间和默认数据源记录。
5. 以后只需输入该密码解锁。右上角的“锁定工作台”会结束当前会话。

内部身份用于继续执行行级权限、任务审计和密钥隔离，但邮箱不出现在界面中。本地开发服务只监听 `127.0.0.1`，默认不对局域网开放。访问密码是工作台解锁凭据，不代替 macOS 账号密码、FileVault 或备份加密。

## 多用户或公网部署

只有需要多人账号、组织 SSO 或公网访问时，才使用部署模式。

1. 部署方在 Supabase Edge Function 的服务端 Secret 中设置 `WORKBENCH_BOOTSTRAP_TOKEN`。它至少为 24 字节的高熵随机值，不得使用前端 `VITE_*` 变量、提交到 Git 或写入数据库。
2. 首次打开已部署 Web UI，输入初始化码、管理员姓名、邮箱和密码。
3. `bootstrap-admin` 在服务端原子占用初始化资格，创建首位管理员。成功后同一初始化码永久失效。
4. 公开 Email、SMS 和通用 signup 必须保持关闭。后续成员由已有管理员创建，或通过已完成域名与成员策略验收的组织 SSO 加入。

## 检查数据源

在右上角“配置”中逐项检查：

- 获客助手：引用服务端 `KC_API_KEY`，浏览器不读取 Key。
- 企查查：使用本机已授权的 `qcc-agent-cli`；连接检查不消耗工商查询额度。
- 用户文件：无外部凭证；支持 CSV、XLSX 和 JSON。
- Ego Lite：检查本机浏览器运行环境。这一步不搜索企业，不使用模型 Token。

## 验证完整流程

使用一批真实但范围可控的数据完成：取数或上传、映射确认、去重、规则运行、企查查核验、Ego Lite 资料采集和导出。只有 GUI、API 和 MCP 返回一致结果，初始化验收才算完成。
